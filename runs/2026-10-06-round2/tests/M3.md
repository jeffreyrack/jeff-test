## 2. Failure audit

### 2a. How the incumbent works

The architecture explains the failures (from the README and input schema on https://apify.com/lukaskrivka/google-sheets):

- **Every append is a full read-modify-write.** "No matter which mode you choose, the actor recalculates how the data should be positioned in the sheet, updates all the cells, and then trims the exceeding rows and columns." So the cost and failure risk grow with the sheet on every scheduled run, and concurrent runs on one sheet race each other.
- **The cell cap is stale.** "Maximum cells in a spreadsheet: 5 million. If you try to import data over this limit, the actor will throw an error and not import anything." Google raised the limit to **10M in March 2022** ([Workspace Updates](https://workspaceupdates.googleblog.com/2022/03/ten-million-cells-google-sheets.html)). Once a scheduled-append sheet crosses the cap, **every later run fails**, which is a repeating failure.
- **No retries on quota errors.** "Google limits how many sheet reads or updates … you can do per minute. If you exceed these limits, the actor run will fail, and no data will be imported."
- **Nested data blows up the width.** Nested arrays are flattened into columns (`hobbies/0`, `hobbies/1`…). Scraper outputs with arrays (reviews, images) produce thousands of columns. That is how a 456-row import hit "5,000,000 cells" (issue of 2026-08-20).
- **Default `limit`** is 250,000 items. There are also `transformFunction` (user JavaScript), `deduplicateByField`, backup modes and `read`/`modify` modes.

So only part of the "auth" bucket is inherent.

- **Input requirements:**
  - **No required field names.** Apify attaches an implicit `payload` (`payload.resource.defaultDatasetId`).
  - Set the integration prefill in **Settings → Integrations** to `{"datasetId": "{{resource.defaultDatasetId}}"}`. Alternatively, read `payload` with `datasetId` as a hidden override.
  - Process the dataset in batches; don't load it all into memory.
- **Native Google integration:**
  - Apify ships **"Upload results to GDrive"** ([docs](https://docs.apify.com/integrations/drive.md)). It uploads a *file* (chosen filename and format) into an `Apify Uploads` folder after each run.
  - It does **not** append or upsert into an existing Google Sheet, so it does not make SheetSync redundant.
  - The incumbent is effectively Apify's native Sheets path: Apify-managed, using Apify's verified Google OAuth.
  - Other substitutes: Zapier, Make and n8n Sheets nodes ([Apify Zapier docs](https://docs.apify.com/integrations/zapier.md)), and Coupler.io.
- **MCP connectors** ([docs](https://docs.apify.com/integrations/mcp-connectors.md)) let Actors call third-party MCP servers with user credentials injected by Apify. But Google needs "Your own OAuth client" (the user registers an OAuth app), which is too much friction for v1.
- **Apify's Google OAuth is not offered to third parties.**
  - The `oAuthAccount.<integrationId>` input used by the incumbent is not in the public input-schema spec. The spec's `resourceType` allows only dataset, key-value store, request queue and `mcpConnector`.
  - The older `apify-google-auth` npm flow ([help article](https://help.apify.com/en/articles/2424053-google-integration)) is the Live-View flow that Google blocked.
  - **So a third-party Actor cannot offer the incumbent's one-click "pick your sheet from Drive" UX.** This is a structural onboarding disadvantage.

## 5. Google Sheets API facts

From the [Sheets usage limits page](https://developers.google.com/workspace/sheets/api/limits), last updated 2026-09-03, unless noted.

- **Quotas:**
  - Reads: **300/min per project** and **60/min per user per project**.
  - Writes: **300/min per project** and **60/min per user per project**.
  - No daily cap within those per-minute quotas.
  - Exceeding a quota returns 429. Google says to use truncated exponential backoff; the quota refills each minute.
- **Service account = one user:** "API calls by a service account are considered to be using a single account." A shared service account therefore gives **60 writes/min across all customers** until an increase is approved.
- **Quota increases:**
  - Currently requested in the Cloud Console. **Approval is not guaranteed.**
  - Pricing: "All standard use of the Google Sheets API is available at no additional cost. **Exceeding the quota request limits is planned to incur charges to your Google Cloud billing account later in 2026.**"
  - From the [Workspace standardized model](https://developers.google.com/workspace/tools-safety): "Later in 2026, following 90 days of notice: Quota increase requests will require Google Cloud billing to be enabled. API usage over standard daily thresholds will generate charges." New projects created from 2026-05-01 get new (lower) quotas for the Gmail, Calendar and **Drive** APIs.
  - **Plan:** a billing-enabled project; avoid Drive API calls.
- **Request limits:**
  - Recommended maximum payload: 2 MB.
  - A request that processes for more than **180 s** times out.
- **Cell limits** ([Google](https://workspaceupdates.googleblog.com/2022/03/ten-million-cells-google-sheets.html), Drive help 37603):
  - **10,000,000 cells per spreadsheet** (the sum over all tabs) and 18,278 columns.
  - So **tab rollover does not help**. Rollover needs a *new spreadsheet*.
  - Service accounts created after 15 Apr 2025 have **0 Drive storage**: they can edit sheets shared with them but cannot create files outside shared drives. So automatic rollover needs either a user-provided "next" spreadsheet ID or a shared drive.
- **Cost:** $0 within quota today. Over-quota billing is coming (date to be announced, with 90 days' notice).

### Ownership-token design (feasible with the Sheets API only)

**Issuing the token.** The token is `base32(HMAC_SHA256(server_secret, APIFY_USER_ID + ":" + spreadsheetId))[:16]`.

- `APIFY_USER_ID` is available in the run environment.
- The first run on an unproven sheet performs **no read of the data and no write**. It ends with a clear message: "Add a tab named `_sheetsync` and put `SS-xxxx` in cell A1." The token is also written to the run's output.

**Checking the token.** On each run, call `spreadsheets.values.get('_sheetsync!A1')`, a 1-cell read, and compare the value in constant time. A named range is also accepted, but the tab plus cell is simpler for no-code users.

**Why the attack fails.** Another Apify user who knows a victim's sheet ID gets a different token. To plant it, they would need edit rights to the sheet already, so there is no escalation through our identity.

**Rules:**

- No replace, upsert or read without proof.
- Re-check the token on every run, so removing the token revokes us.
- Cache the result per run only.
- No row data in logs.

**Cost:** one extra read per run. A one-time setup failure counts against the public success rate; budget about 1 failed run per new user.

## 8. v1 build spec (minimum reliable Actor)

Again, this applies only if the placement precondition is met.

### Modes

- `append` (default): true `spreadsheets.values.append` with `INSERT_ROWS`. **Never read the existing body.**
- `upsert-by-key`:
  - read only the key column;
  - batch-update changed rows;
  - append the new ones.
- `replace`: clear the tab, then write. **Allowed only with ownership proof**, like everything else.
- **No** `read`, `modify`, `load backup` or user-JavaScript `transformFunction` modes in v1.

### Input

| Field | Notes |
|---|---|
| `spreadsheetUrl` | Accept a URL or an ID. Validate the ID pattern **without** a fixed 44-character rule. |
| `sheetName` | Created if missing. |
| `mode` | append / upsert-by-key / replace |
| `keyField` | for upsert |
| `columns` | optional allow-list and order |
| `maxColumns` | default 200 |
| `nestedHandling` | `json-string` (default) or `flatten`, with a depth cap |
| `datasetId` | under Advanced. The default comes from `payload.resource.defaultDatasetId`. |
| `serviceAccountJson` | optional, `isSecret`, for bring-your-own credentials |

**Integration prefill:** `{"datasetId": "{{resource.defaultDatasetId}}"}`.

### Auth

- Shared service account plus the ownership token (§6), or bring-your-own service-account JSON.
- The shared service account lives in a **billing-enabled GCP project under a personal account, not a Workspace org**, because a Workspace org blocks key creation. Use one project and do not shard projects to evade quota (legal note).

### Reliability

- Stream the dataset in pages of 5–10k items.
- Write in chunks of ≤ 2 MB, at most about 5k rows per request.
- Use a global token-bucket pace of ≤ 50 writes/min per service account, using a named key-value store as a lightweight lock.
- On 429, 500 or 503: truncated exponential backoff with jitter, up to 64 s, at most 8 retries.
- Each request must stay well under Google's 180 s limit.

**10M preflight:**

- Call `spreadsheets.get` (only the `gridProperties` fields) to sum the cells across all tabs.
- If the write would exceed 9.5M cells, **fail before writing** with an exact remedy: start a new spreadsheet or trim the columns.
- Warn at 80%.

**Idempotency:**

- Keep a checkpoint `{sourceRunId, offset}` in a named key-value store in the user's account, so a retried run resumes without double-writing.
- Header handling: union the headers, add new columns on the right, and never reorder existing ones.

**Failure output:**

- One-line causes with a classification (USER_NOT_SHARED / USER_BAD_ID / USER_NO_TOKEN / QUOTA / GOOGLE_5XX / INTERNAL).
- The classification feeds the actor-attributable metric.

### Resources

- 256 MB memory by default, 512 MB when allowed. Streaming keeps memory flat.
- Timeout 3,600 s.
- Expect $0.0003–0.002 platform cost per typical run.

### PPE events

- `run-start`: $0.005
- `rows-written`: $0.30 per 1,000, charged per chunk **after** Google confirms the write, so failed rows are never charged.

### README

- Factual comparison only: "Apify public stats, 2026-10-06: 49% of runs succeeded".
- A switching table, field by field from the incumbent.
- Data handling: no row data in logs; GDPR processor terms; acceptable-use policy.

- Status tab
